# Reporting and operating securely

Do not post engine API keys, `config.xml`, private certificate/key files, account cookies, pairing screenshots containing private filenames, or synchronized documents in a public issue. Report a vulnerability privately to `support@afrosoftware.com`.

Verify the release checksum and official source before running an unsigned preview. The optional Windows service installer runs under the low-privilege LocalService account with the dedicated service SID `NT SERVICE\DesksyncSync`, grants that SID access to its private configuration and shared folder, and limits its administrative interface to loopback. The private configuration and newly created server folder are restricted to administrators, SYSTEM, the installing user and the service SID. Existing folder permissions are preserved; review them if reusing a directory.

The first hosted console is owner-only. A successful Afrosoftware login does not grant access to someone else's storage. Desktop peers must be explicitly approved on both ends. Revocation prevents future transfers but cannot erase previously downloaded files.

Public discovery and encrypted relays are enabled in the engine. Router port mapping is disabled. If your organization disallows public discovery, configure private discovery/static peer addresses through Syncthing's documented settings and verify connectivity. Do not expose port 5391 or share the private engine profile.

Version 0.2 checks signed update metadata from the official website and GitHub release assets. It verifies an embedded RSA public key, archive length and SHA-256 before replacement, keeps private configuration and synchronized files outside the payload, and restores the previous application if startup health checks fail. Server updater staging and helper executables are restricted to administrators and SYSTEM. Private release keys must remain outside the repository, website and packaged files. Forks must use their own signing key and update policy.

Our hosted desktop sign-in requires an explicitly approved, expiring device request and the verified server owner. Desktop bearer sessions are narrowly scoped, stored as hashes on the server and encrypted for the current Windows user on the desktop. Browser credentials and engine API keys never enter the renderer. Sign out to revoke the current session and remove its device trust; removing a peer cannot erase previously synchronized files. Self-hosted deployments can pair with connection files without an online account.

Back up data independently and monitor upstream Syncthing security notices. The 30-day version history covers remotely replaced/deleted files and is not a full backup or ransomware-recovery guarantee. Update metadata signatures do not replace a trusted Windows executable code-signing certificate; the preview still has an unknown publisher in SmartScreen.

Version 0.3 uses non-zero fixed disk-space reserves when migrating the inherited percentage defaults. Custom limits are preserved. Hosted device-health reports are authenticated to the reporting device, validated against a small field whitelist, and stored in the private server profile. They include counts, free space, selected sync errors and version information; they never include account tokens, engine keys, file contents or raw logs. Stale reports are excluded from the live UI. The report endpoint cannot change sync configuration or other devices' permissions.
